このフォルダ `gachi/` には、研究室サイトの**新しいデザイン**が入っています。
リポジトリ直下の `HANDOVER.md`（現在のデザインのマニュアル）とあわせて読んでください。

> **いまの公開状況（2026年9月時点）**
>
> | | URL | 検索結果 |
> |---|---|---|
> | 現在のデザイン（本番） | https://shintani-lab.github.io/ | 出る |
> | 新デザイン（比較用） | https://shintani-lab.github.io/gachi/ | 出ない |

> 先生にどちらを本番にするか選んでいただく段階です。
> 新デザインを本番にする場合の作業は、このファイルの最後の「新デザインを本番にする場合」にあります。

## いちばん大事なこと

**文章・メンバー・業績・お知らせ・写真は、2つのデザインで共通です。**

新デザインは、リポジトリ直下の `content/`（文章）と `public/`（写真など）を**そのまま読み込んで**います。
`gachi/` の中に文章のコピーはありません。

そのため、**更新の手順は直下の `HANDOVER.md` とまったく同じ**です。
`content/` のファイルを直してコミットすれば、2〜3分後に**両方のデザインに同時に反映**されます。

このファイルでは、**新デザインだけにある仕掛けと、その注意点**を説明します。

## 手元で見るとき

**通常の更新には不要です。** デザインを変えたいときだけ使います。

```bash
cd shintani-lab.github.io   # リポジトリの直下
npm ci                       # 初回だけ（2つのデザインで共通の部品を入れます）
cd gachi
npm run dev
```

`http://localhost:4321` をブラウザで開きます。止めるときは Ctrl + C です。

- 新デザインのための追加インストールはありません。部品（Astro と js-yaml）は共通です。
- **OneDriveやiCloudの同期フォルダの中に置かないでください**（直下の `HANDOVER.md` と同じ理由です）。

### キャッチコピーを変えたとき

トップの冒頭の「解析」は、キャッチコピーを**手作業で**形態素と文節に分けたデータ
（`gachi/src/lib/lang.ts` の `heroParse`）を使っています。

`content/site.yaml` のキャッチコピーを書き換えると、このデータと一致しなくなります。
その場合は**エラーにはならず、演出をやめて普通の大きな見出しとして表示されます**。
サイトが壊れることはありません。

新しいキャッチコピーでも演出したいときは、`heroParse` を作り直します。書き方はこうです。

```ts
{ head: 3, tokens: [
  t('データ', 'noun', { reading: 'データ' }),
  t('で', 'particle', { sub: '格助詞', reading: 'デ' }),
] },
```

- `{ ... }` の1つが**文節**1つです。上から文の順に並べます。
- `tokens` の中の `t(...)` の1つが**形態素**1つです。
  `t('表層形', '品詞', { 読みなど })` の形で書きます。
- 品詞は `noun`（名詞）、`verb`（動詞）、`particle`（助詞）、`aux`（助動詞）、
  `suffix`（接尾辞）、`symbol`（記号）から選びます。
- `head` は、**係り先の文節の番号**です。番号は上から 0, 1, 2 … と数えます。
  文末の文節だけは `-1` にします。
- `base`（原形）、`reading`（読み）、`form`（活用形）、`sub`（品詞の細かい分類）は、
  語にカーソルを合わせたときの説明に出ます。省略もできます。
- **すべての形態素をつなげた文字列が、キャッチコピーと1文字も違わず一致したときだけ**、演出が出ます。

> 形態素解析ツール（MeCab や GiNZA など）の結果を参考にすると作りやすいです。
> ただし、**品詞や係り受けは専門の先生が見る部分です。公開前に必ず先生に確認してください。**

### 学生のアイコン

顔写真の代わりに、**名前の文字から自動で作った模様**を表示しています。

- 名前の文字を「ハッシュ」という計算で1つの数字に変え、その数字から
  5×5マスのどこを塗るか（左右対称）と、色（5色のどれか）を決めています。
- **同じ名前からは、いつ・どのパソコンで作っても同じ模様**になります。
  名前を1文字でも変えると、まったく違う模様になります。
- 計算はサイトを作るときに行っており、名前を外部のサービスに送ることはありません。
- `name` を書き忘れた場合は、学年の文字から模様を作ります。

作り方は `gachi/src/lib/lang.ts` の `identicon` にあります。

### 時間割表

`content/join.yaml` の `seminar.slots` に、次の形で書かれた行が表に描かれます。

```yaml
slots:
  - 学部4年生・大学院生合同ゼミ：水曜3・4限
  - 学部3年生ゼミ：水曜4・5限
  - 大学院生の個別指導：スケジュールを調整し、他曜日に実施
```

- `名前：〇曜△・□限` の形です。区切りの `：` は**全角**です。
- 時限は `3・4限` のほかに、`3〜5限` のような範囲の書き方も読み取れます。
- 形に合わない行（上の例の3行目）は、**表の下に文章のまま**並びます。エラーにはなりません。
- どの行も形に合わないときは、表を描かずに文章の一覧だけを出します（内容は消えません）。
- 時間が重なるゼミは、同じ曜日の中で横に並べて描きます。

## 困ったとき

| 症状 | 原因と対処 |
|---|---|
| トップの「解析」の演出が出ず、普通の見出しになった | キャッチコピーを書き換えたためです。上の「キャッチコピーを変えたとき」を参照 |
| ゼミの時間割表が出ず、文章の一覧だけになった | `slots` のどの行も `名前：〇曜△・□限` の形になっていません。`：` が全角か、`曜` と `限` が入っているかを確認 |
| 表に出てほしいゼミが、表の下に文章で出る | その行の書き方が形に合っていません。上と同じ確認をしてください |
| 学生のアイコンの模様が変わった | 名前の文字が変わったためです（空白の有無も含みます）。模様は名前から決まります |
| 動きがほとんどない | その端末で「視差効果を減らす」（動きを減らす）設定がオンになっています。**意図した動作です**。動きが苦手な人のために、自動で動く演出を止めています |
| ページを切り替えたときに、ふわっとした動きがない | ブラウザが対応していないためです（Chrome・Edge・Safari は対応）。表示には問題ありません |
| GitHubの Actions で赤い×が出て、ログに `gachi` と出ている | 新デザイン側のビルドの失敗です。**この場合、現在のデザインの更新も止まります**（公開中のサイトは壊れません）。直前の変更を Revert して相談してください |

## 仕組みのメモ（技術的な話）

| ファイル | 役割 |
|---|---|
| `gachi/src/pages/` | 各ページ。URLの構成は現在のデザインと同じです |
| `gachi/src/layouts/Layout.astro` | ヘッダー・フッター・SNS用の情報・ページ切り替えの動き・スクロールで現れる動き |
| `gachi/src/styles/gachi.css` | 色・文字・余白の設定。先頭の `:root` にまとまっています |
| `gachi/src/lib/data.ts` | `content/` の読み込み、メニューの一覧（`nav`）、公開場所に合わせたURL（`url()`） |
| `gachi/src/lib/types.ts` | `content/` の YAML の形。**YAMLに項目を足したら、直下の `src/lib/content.ts` とこのファイルの両方に足してください** |
| `gachi/src/lib/lang.ts` | 品詞の色・キャッチコピーの解析結果・各ページタイトルの品詞・学生アイコンの計算 |
| `gachi/src/components/Hero.astro` | トップの冒頭の「解析」 |
| `gachi/src/components/Pipeline.astro` | 研究内容ページの、スクロールで形が変わる図 |
| `gachi/src/components/Timetable.astro` | ゼミの時間割表 |
| `gachi/src/components/Identicon.astro` | 学生のアイコン |
| `gachi/src/components/PageHead.astro` | 各ページの大きなタイトル（品詞つき） |
| `gachi/src/pages/sitemap.xml.ts` | 検索エンジン向けのサイトマップ |

- **サイト全体の色は「品詞の色」です。** 名詞＝青、動詞＝朱、助詞＝緑、助動詞＝紫、
  接尾辞＝黄、記号＝灰。`gachi.css` の `--noun` などで変えられます。
  白地の小さな文字には、読みやすさの基準を満たす濃い色（`--noun-ink` など）を使っています。
- 新デザインは `gachi/` の中だけで完結しています（`content/` と `public/` と、共通の部品を除く）。
  現在のデザインの `src/` を消しても、新デザインは動きます。
- 文字は Google Fonts から読み込んでいます（Zen Kaku Gothic New、Inter、M PLUS 1 Code）。
- 外部のライブラリは使っていません。図や動きは、すべて手書きのコードです。
- 「視差効果を減らす」設定の端末では、自動で動く演出（冒頭の解析・流れる帯など）を止めて最後の状態を表示し、
  スクロールに合わせて変わる図は、途中の動きを省いて切り替えます。

### 公開場所の切り替え（`/` と `/gachi/`）

- 公開は `.github/workflows/deploy.yml` で行っています。いまは、現在のデザインを `/` に、
  新デザインを `/gachi/` に置いています。
- 新デザインは、環境変数 `GACHI_BASE` を付けてビルドすると、その場所（`/gachi/`）の下に公開する形になり、
  **自動で「検索結果に出さない」設定と、画面右下の「現在のサイトで見る」ボタン**が付きます。
  付けずにビルドすると、本番用（検索結果に出る・ボタンなし）になります。
- そのため、**サイト内のリンクや画像のパスは、必ず `url('/research/')` のように `url()` を通して書いてください。**
  `href="/research/"` と直接書くと、`/gachi/` で公開しているときにリンクが切れます。

### ページを増やすとき

直下の `HANDOVER.md` の2つに加えて、**タイトルの品詞**の作業が必要です。

1. `gachi/src/pages/` の中の `contact.astro` などをコピーして名前を変え、中身を書き換える
2. `gachi/src/lib/data.ts` の `nav` に1行足す
3. `gachi/src/lib/lang.ts` の `titles` に、新しいページのタイトルを語に分けて足す

## 新デザインを本番にする場合

新デザインは、SNS用のプレビュー、正式なURLの指定（canonical）、サイトマップ、404ページなど、
本番に必要なものをすでに備えています。**切り替えは `.github/workflows/deploy.yml` の書き換えだけ**です。

`deploy.yml` の、次の部分を

```yaml
      - run: npm ci
      - run: npm run build
      # 新デザイン（gachi/ フォルダ）を、比較用に /gachi/ の下へ公開します。
      # 新デザインを本番にするときは、gachi/HANDOVER.md の「新デザインを本番にする場合」を見てください。
      - name: Build gachi (comparison)
        run: npx astro build --root gachi
        env:
          GACHI_BASE: /gachi/
      - run: cp -r gachi/dist dist/gachi
      - uses: actions/upload-pages-artifact@v5
        with:
          path: ./dist
```

このように書き換えてコミットします。

```yaml
      - run: npm ci
      - run: npx astro build --root gachi
      - uses: actions/upload-pages-artifact@v5
        with:
          path: ./gachi/dist
```

- 2〜3分後、https://shintani-lab.github.io/ が新デザインになります。`/gachi/` は無くなります。
- **元に戻したいときは、このコミットを Revert するだけ**です（直下の `HANDOVER.md` の「困ったとき」を参照）。
- `content/` と `public/` は元から共通なので、移す作業はありません。
- 切り替えたあと、落ち着いたら次の片付けをしてください（急ぎではありません）。
  - 直下の `HANDOVER.md` の内容のうち、見た目に関わる部分（`src/` の説明）を、このファイルの内容に置き換える
  - 使わなくなった現在のデザインの `src/` を消すかどうかを決める（消しても新デザインは動きます）
